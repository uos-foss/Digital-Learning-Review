For school leadership and school administrators using the School Dashboard.

### What does the School Dashboard actually tell me?

Where to direct attention. It is a picture of how modules in your school are set
up in Blackboard, covering template sections in place, accessibility of the
content and reading lists published, drawn from institutional systems and from
the audits Digital Learning Advisors carry out.

It is not a measure of teaching quality, and it cannot be used as one. See
"What this cannot tell you" at the bottom.

### There are two compliance figures and they don't match. Which is which?

They have deliberately different denominators, and the difference matters:

* **Template Alignment** (the tab on this dashboard, and the tab of the same
  name on the Faculty Overview) covers **every module in the school**. A module
  an advisor has audited uses their recorded answer. A module nobody has
  audited falls back to the Template Alignment Report's own data, so it is not
  counted as a failure merely for being unaudited.
* **VLE Compliance** (the School Comparison table on the Faculty Overview)
  covers **submitted audits only**, because for a school-against-school
  comparison an unaudited module tells us nothing.

Always read VLE Compliance alongside the **Audited %** column beside it. A high
figure drawn from four audited modules is not the same claim as one drawn from
most of the school.

### Why are so few modules audited?

Because manual auditing does not scale. A small team cannot review every module
in the faculty, and it was never the intention that they would.

The institutional data does the bulk of the compliance checking automatically,
across all modules. Advisors' time goes on spot-checks, a sample chosen by
judgement, and on the modules the data flags as most likely to need it. A low
audited percentage is the design working, not a backlog.

### What are spot-checks and what does the agreement figure mean?

A Digital Learning Advisor flags a module for a closer look, based on their own
judgement: experience, a spread across levels, some deliberate randomness.
Nothing auto-samples, by design. That judgement belongs with the advisors.

When the module is then audited, what the advisor actually recorded is compared
against what the data predicted at the moment it was flagged. The agreement
figure is how often the two matched.

**It measures the data, not the advisor.** Low agreement means the automated
signals are a poor guide for that kind of module, which is worth knowing. It is
not a performance measure of anybody.

### Can I read what the advisor actually said about a module?

Yes, for modules that were spot-checked. The School Dashboard's Spot-Check
Comments tab shows the advisor's own Additional Comments in full, most recently
written first, one card per module, with the module name and who audited it.
You can search across them, narrow to checked or pending flags, and export what
is on screen as a CSV.

This is the part of the audit that says what is actually wrong with a course in
an advisor's own words, rather than as a status. It is worth reading alongside
the figures, not instead of them.

Two things to keep in mind. Only flagged modules appear there, and only a
handful are flagged each year, so it is a sample rather than a survey of the
school. A comment on a module audited months ago describes the course as it was
then.

### Why do average Ally scores exclude some courses?

Because a freshly rolled-over course contains only its template, a couple of
files and a couple of dozen editor pages, and Ally scores that close to 100%
simply because there is almost nothing in it to find fault with. Averaging
those in would band every school green through the autumn.

Averages and rankings therefore cover only courses marked **In progress**.
Early in the year, how many courses have started is the more useful number than
the score.

### A module in my school shows no activity at all. Is that a problem?

Not necessarily, and it is worth checking which of these it is before raising
it:

* The course is genuinely not built yet, which is normal in the run-up to a
  semester.
* The module is not really running: a skeleton shell, merged into another
  module, or an archived record. These can be marked inactive so they stop
  dragging down the school's figures.
* The module was missing from the last export. Check the sidebar import dates.

### How current is any of this?

Every source except the audits is a periodic snapshot, not a live feed. The
sidebar caption gives the import date for each. Before taking a figure into a
meeting, check how old the data behind it is, particularly in the autumn when
courses change faster than the import cycle.

There is a second lag worth knowing about. Once an advisor has audited a
module, their recorded answer takes precedence over the data permanently, so a
later import will not revise it either way. That keeps the data from
contradicting somebody who went and looked, but it means an audited module only
moves when a person revisits it.

### What this cannot tell you

Everything automated here measures **presence and process**: whether a section
is visible, whether it has been edited, whether a reading list exists, whether
a PDF is tagged for a screen reader. None of it measures whether the content is
good, current or well taught.

A visible, edited section is evidence that somebody did something to it. It is
not evidence that what they did was any good. A module reading well on every
indicator here can still be taught badly, while an excellent module can show
findings because its assessment brief is still hidden.

Used as intended, this is a tool for making sure students can find and use what
their lecturers have prepared. Used as a performance measure of individuals, it
would be measuring the wrong thing with the wrong instrument.
