These questions come up whatever your role. The tabs above cover what is
specific to Digital Learning Advisors, module leads and school leadership.

### Where do the numbers on this site come from?

Four institutional systems, plus the audits advisors record here:

| Source | What it tells the portal |
| :--- | :--- |
| **SITS** | The module list, module leads, teaching periods and assessment strategy |
| **Blackboard Template Alignment Report** | Which required template sections are visible, hidden, deleted or missing in each course, and when each was last changed |
| **Ally** | Accessibility scores and the specific issues found in each course's files and pages |
| **Leganto** | Whether a module has a reading list, and whether it is Draft or Published |
| **Audits** | What a Digital Learning Advisor recorded when they reviewed the module |

### Is the data live?

**No. Everything except the audits is a snapshot.** Each of those four systems
is exported to a file and imported into the portal periodically. Between
imports the portal shows you exactly what the last export said, however much
has changed in Blackboard since.

The sidebar caption, *"Latest data from: SITS (…), Blackboard Template
Alignment (…), Ally (…), Leganto (…)"*, gives the date of the most recent
import for each source. It is worth a glance before you draw a conclusion from
anything on screen, particularly early in the year when courses change daily.

Audits are the exception. They are saved into the portal's own database the
moment someone presses Save, and appear immediately.

### My module changed in Blackboard. Why hasn't the portal caught up?

Almost always because there has not been an import since you made the change.
Check the sidebar dates.

There is a second reason that applies only to the template sections. If a
Digital Learning Advisor has already audited the module, their recorded answer
takes precedence over the data permanently, so a later import will not change
it. See the **For Digital Learning Advisors** tab for why that is deliberate.

### Why is there no "complete" or "finished" state for a course?

Because nothing in the data could honestly tell us that. Module leads build
their courses just-in-time throughout the year, often right up to the final
assessment, so there is no point at which a file count or a section status
proves a course is finished. The portal therefore has only two positive build
stages:

* **Not started**: the course still holds only its rolled-over template.
* **In progress**: there is content beyond the template.

That is also why accessibility averages and rankings only count courses marked
*In progress*. An untouched template scores close to 100% because there is
almost nothing in it for Ally to find, and including those would make every
school look excellent through the autumn.

### What does the portal *not* measure?

Quality. Every automated signal here measures presence and process: whether a
section is visible, whether it has been edited, whether a reading list exists,
whether a PDF is tagged. None of that says whether the content is good,
current or well taught. A visible, edited section is evidence that somebody did
something to it, and nothing more.

That gap is the reason human audits exist alongside the data, and the reason a
saved audit answer always overrides an automated signal.

### Who can see what?

The sidebar only shows the pages your account can reach.

* **Module report**: everyone. Accounts tied to a school see modules in that
  school.
* **School Dashboard**: school leadership, school administrators, Digital
  Learning Advisors and faculty-wide accounts.
* **Faculty Overview**: faculty-wide accounts and Digital Learning Advisors.
* **Audit Portal**: Digital Learning Advisors and administrators only.

### Something here looks wrong. What do I do?

Use the **App Feedback** tab on this page. If it is a data problem rather than a
portal problem, such as a module missing, the wrong module lead, or a course
that isn't really running, say so. Those are fixed by a re-import or in the
Admin Panel rather than by a code change.
